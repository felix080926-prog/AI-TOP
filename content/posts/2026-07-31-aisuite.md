**大家好，我是雷达君。**

你可能用过 OpenAI 的 GPT-4，也试过 Anthropic 的 Claude，可能还在本地跑过 Ollama。每个模型都有自己的 API、自己的 SDK、自己的认证方式。

你想对比一下 GPT-4 和 Claude 对同一个问题的回答——你得写两套代码、调两套接口、处理两种不同格式的返回结果。你想从 GPT-4 换到 Claude——你得重写一半的调用逻辑。你想在生产环境里同时用三个模型做 A/B 测试——你的代码里会塞满`if provider == "openai"`这样的条件判断。

**这就是大模型世界的现状：模型越来越强，但接入越来越烦。**

今天雷达君要安利的这个开源项目，就是来解决这个问题的。它由**AI 领域标志性人物、斯坦福大学教授吴恩达（Andrew Ng）** 亲自下场打造，是一个极其轻量的 Python 库——**核心只有几百行代码**——让你用一套统一的 API 调用所有主流大模型。

它就是——**aisuite**。

## 01 ｜核心逻辑：几百行代码，终结 API 碎片化

aisuite 的核心理念可以用一句话概括：**一套代码，通吃所有大模型**。

今天的大模型市场是什么样子？OpenAI 有 GPT-4o、GPT-5，Anthropic 有 Claude 3.5/4，Google 有 Gemini，Mistral 有自家模型，AWS Bedrock、Azure OpenAI、Groq、HuggingFace、Ollama……每个提供商都有自己独特的 API 结构、认证机制和响应格式。

开发者要同时维护多个提供商的集成，开发复杂性剧增，项目时间表延长，大量技术债务堆积。

吴恩达在构建应用时也遇到了同样的问题——**与多个提供商集成非常麻烦**。他的解决方案是：做一个轻量级的**统一包装器**，把各家 SDK 的差异全部抹平。

使用 aisuite 时，你只需要改一个字符串，就能在模型之间随意切换：

```python
# 用GPT-4o
model="openai:gpt-4o"

# 换Claude，只改这一个字符串
model="anthropic:claude-3-5-sonnet-20241022"

# 换本地Ollama，还是只改一个字符串
model="ollama:llama3.1:8b"
```

**其他代码，一行都不用改**。

## 02 ｜硬核功能盘点

> 🔗 **GitHub 地址**：https://github.com/andrewyng/aisuite

### 1. 两层架构：Chat Completions + Agents API

aisuite 的设计非常克制，只做了两层：

**第一层：统一的 Chat Completions API**——一个类似 OpenAI 风格的接口，覆盖**13+主流 LLM 提供商**。目前支持 OpenAI、Anthropic、Azure、AWS、Google、Groq、Mistral、HuggingFace、Ollama、OpenRouter、Cohere、Cerebras、Sambanova 等。你在这层做的事情就是调用模型、获取回答——最基础的 LLM 交互。

**第二层：Agents API + Toolkits + MCP**——在第一层之上构建 Agent 能力。这层支持多轮对话、工具调用（把 Python 函数作为工具传给模型）、状态管理、追踪，以及 MCP（模型上下文协议）集成。你在这层做的事情是让 AI 不仅能“说话”，还能“干活”——读文件、操作 Git、执行 Shell 命令。

**从“聊天”到“干活”，aisuite 用两层架构全部覆盖。**

### 2. 统一音频 API：不只是文本

aisuite 的野心不止于文本模型。它还提供了一个**统一的音频 API**，支持 OpenAI 的 Whisper、Deepgram 和 Google 等语音识别服务。用同一套接口调用不同提供商的 ASR（自动语音识别）服务——和文本模型一样，换提供商只需要改一个字符串。

### 3. MCP 原生支持：连接外部工具和数据源

aisuite 原生集成了**MCP（模型上下文协议）** ，让 AI 应用可以连接到外部数据源和工具。这意味着你可以通过 aisuite 把 MCP 服务器和它的工具暴露给 AI 提供商——无论你用的是 OpenAI、Anthropic 还是本地 Ollama。

### 4. OpenCoworker/OpenWorker：吴恩达亲手打造的桌面 AI 同事

这个仓库不只是 aisuite 的代码库，还是**OpenCoworker（也叫 OpenWorker）的所在地**——一个基于 aisuite 构建的桌面 AI 助手。

OpenCoworker 能做什么？它能聊天、做深度研究、在你的电脑上执行任务。它可以读取文件（经你授权）、收发 Slack 和邮件、生成 PDF 报告和电子表格。它支持定时自动化任务，比如每天早上给你一份新闻摘要。

**这相当于吴恩达团队用 aisuite 做了一个“参考实现”** ——你不仅能直接用这个桌面 App，还能参考它的源码，用 aisuite 构建你自己的 Agent 框架。

**数据主权完全在你手里**：OpenCoworker 需要你自己带 API Key（OpenAI、Anthropic、Google），或者用 Ollama 完全本地运行——你的数据永远留在你自己的机器上。macOS 和 Windows 都支持。

### 5. 极简安装：一行命令，按需选择

aisuite 的安装极其灵活。你可以只装基础包，不加任何提供商的 SDK：

```bash
pip install aisuite
```

也可以带上特定提供商：

```bash
pip install 'aisuite[anthropic]'
```

或者一次性装上所有提供商：

```bash
pip install 'aisuite[all]'
```

**你用多少，装多少，不浪费一点空间。**

> **现实摩擦提醒**：aisuite 目前尚不支持流式输出（streaming），也不支持速率限制和 Token 用量监控。如果你需要这些能力，它可能还不是最成熟的方案。但团队明确表示正在积极开发中，未来会覆盖更多用例。

## 03 ｜横向对比

在“统一 LLM 接口”这个赛道里，aisuite 和 LiteLLM 是最常被放在一起比较的两个项目：

| 维度              | **aisuite**                   | **LiteLLM**            |
| :---------------- | :---------------------------- | :--------------------- |
| **创始人**        | **吴恩达（Andrew Ng）**       | 社区驱动               |
| **代码体量**      | **几百行**，极简              | 功能更丰富，代码量更大 |
| **核心定位**      | 轻量统一接口 + Agent 能力     | 企业级 LLM 网关        |
| **Agent 能力**    | ✅ 原生 Agents API + Toolkits | ✅ 支持                |
| **MCP 支持**      | ✅ 原生集成                   | ✅ 支持                |
| **流式输出**      | ❌ 暂不支持                   | ✅ 支持                |
| **速率限制/预算** | ❌ 暂不支持                   | ✅ 支持                |
| **Web UI**        | ❌ 无                         | ❌ 无                  |
| **桌面 App**      | ✅ OpenCoworker（参考实现）   | ❌                     |
| **典型用户**      | Python 开发者、AI 研究者      | 企业级多模型治理       |

**简单说：LiteLLM 是功能更全的“企业级网关”，aisuite 是吴恩达亲手打造的“极简统一接口”**。如果你追求轻量、干净、有 Agent 能力，选 aisuite。如果你需要流式输出、速率限制、预算管理等企业级特性，LiteLLM 可能更成熟。

## 04 ｜典型场景和避坑

**适合谁用？**

- **想在多个 LLM 之间快速切换和对比的 AI 开发者/研究者**：改一个字符串就能换模型，做 A/B 测试极其方便
- **想用一套代码同时调用多个模型的应用开发者**：不用为每个提供商写不同的集成代码
- **想构建 Agent 但不想从零搭工具调用框架的开发者**：aisuite 的 Agents API + Toolkits 帮你省掉大量样板代码
- **想参考吴恩达团队如何构建 Agent 桌面应用的学习者**：OpenCoworker 的源码就是最好的教材

**不推荐给谁？**

- **需要流式输出、速率限制、预算管理的生产级场景**：aisuite 目前还不支持这些特性
- **需要 Web UI 来管理多模型调用的团队**：aisuite 和 LiteLLM 都没有提供 Web 界面
- **需要对接国内大模型（如文心、通义、智谱）的场景**：aisuite 目前主要支持国外生态

## 05 ｜快速上手指南（2 分钟）

**第 1 步：安装**

```bash
pip install 'aisuite[all]'
```

**第 2 步：设置 API 密钥**

```bash
export OPENAI_API_KEY="your-openai-key"
export ANTHROPIC_API_KEY="your-anthropic-key"
```

需要用什么模型就设什么 Key。

**第 3 步：写代码**

```python
import aisuite as ai

client = ai.Client()

messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "解释一下什么是量子计算"}
]

# 用GPT-4o
response = client.chat.completions.create(
    model="openai:gpt-4o",
    messages=messages,
    temperature=0.75
)
print(response.choices[0].message.content)

# 换Claude，只改model参数
response = client.chat.completions.create(
    model="anthropic:claude-3-5-sonnet-20241022",
    messages=messages,
    temperature=0.75
)
print(response.choices[0].message.content)
```

**同样的代码，换一个字符串就是换一个模型**。

> **验证安装成功**：运行上述代码，如果能正常返回两个模型的回答，说明安装成功。

**想试试桌面版 OpenCoworker？** 直接去 GitHub Releases 下载 macOS 或 Windows 安装包——不需要写一行代码，下载就能用。

## 06 ｜总结

aisuite 解决了一个被很多人忽视但极其致命的问题：**大模型越多，接入越烦**。

OpenAI 有 OpenAI 的 API，Anthropic 有 Anthropic 的 SDK，Google 有 Google 的认证方式。你想用三个模型做对比测试，就得写三套代码、调三套接口、处理三种不同的返回格式。这还不算 AWS Bedrock、Azure、Groq、Mistral、HuggingFace……每一家都有自己的“方言”。

吴恩达的解法极其克制：**几百行代码，一个统一接口**。你用一套 API 调所有模型，换提供商只改一个字符串。它不做功能堆砌，不做花哨的 UI，只解决一个核心问题——**让开发者不再被 API 碎片化折磨**。

吴恩达亲自主导，OpenCoworker 桌面 App 作为参考实现——aisuite 正在把“多模型集成”这件事，从“噩梦”变成“几行代码”。

这不是一个功能最全的工具，但它是**最干净、最直接、最能让你立刻用起来的工具**。

安装包和完整代码都在 GitHub 上：https://github.com/andrewyng/aisuite
