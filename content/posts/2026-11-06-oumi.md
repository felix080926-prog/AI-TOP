11 月 4 日，企业 AI 平台 Oumi 发布了一项更新：自家的「AI 工程师」FAiE 现在能端到端地帮企业造 Agent，连 Agent 背后那个模型一起训出来。消息当天就被 SiliconANGLE、TokenPost 等多家科技媒体接过去报道，Oumi 创始人 Manos Koukoumidis 在社交平台上的说法很直接——大家都在用 AI Agent 自动化一切，唯独 AI 工程本身还得人来做，这事说不通。

![Oumi 平台上的 FAiE 界面](https://mintcdn.com/oumi/D0vKyXNqx2ohrLV9/images/faie-page.jpg)

Oumi 抛出的判断是：Agent 做 demo 容易，做可靠难。一个跑不通的 Agent，可能是提示词写歪了，可能是工具调用断了，也可能是底下那个模型本身不够用。前两个问题社区已经卷得差不多了，提示词模板和 harness 框架一抓一大把；真正卡住的是第三个——模型权重没为具体任务调过，改提示词也只是在别人的模型上打补丁。

这次更新给了三样东西。一是端到端的 Agent 开发流程，从定义任务、工具、环境，到评测、训练、部署、持续改进，全部放进一条流水线，线上失败会变成下一轮的评测集和训练数据。二是 Bring Your Own Harness，已有的编排、工具、记忆、业务逻辑都不用动，接到 Oumi 上做评测和训练即可。三是训练方法从 SFT 扩到 DPO，再用 GRPO 按任务结果做强化学习，其中 GRPO 目前还是私有预览。

趋势说完了，还有个更实际的问题：上面这套是企业平台，个人开发者和小团队怎么用？答案是背后那套开源框架。

**项目地址：** https://github.com/oumi-ai/oumi

oumi-ai/oumi 就是 Oumi 的开源底座，目前 9400 多 Star，今天一天涨了 650 多。它做的事情和平台一致，但完全跑在自己的机器上：微调（SFT/DPO/GRPO）、评测、合成数据、推理、部署，一条命令配一个配置文件。

![Oumi 平台的任务界面](https://mintcdn.com/oumi/D0vKyXNqx2ohrLV9/images/jobs-page.jpg)

它的核心设计是「配置即实验」：训练、评测、推理共用同一套 YAML 配置和同一个 CLI，换模型、换数据集、换训练方法基本只改配置不动代码。0.9 版本之后 Agent 场景被补上了——工具调用的 SFT/DPO、可执行的工具环境、能跑在任意 Oumi 环境上的 GRPO（底层用 verl），还有一个多标准的 RubricJudge 用来给模型输出打分。模型侧支持 Qwen、Gemma、DeepSeek R1 这些主流开源家族，训练完还能用 `oumi launch up` 一键推到 GCP、AWS、Azure 或 Lambda 上跑。

装起来只要两条命令，基础版和 GPU 版各一条：

```bash
uv pip install oumi            # 基础安装
uv pip install 'oumi[gpu]'     # 需要 GPU 支持
```

没有 uv 用 pip 也一样。想跳过环境配置就直接拉官方镜像：

```bash
docker pull ghcr.io/oumi-ai/oumi:latest
docker run --gpus all -it ghcr.io/oumi-ai/oumi:latest oumi --help
```

装完跑一遍官方给的 135M 小模型配方，几分钟就能看到训练加评测的完整链路：

```bash
oumi train -c configs/recipes/smollm/sft/135m/quickstart_train.yaml
oumi evaluate -c configs/recipes/smollm/evaluation/135m/quickstart_eval.yaml
```

![在 Oumi 平台创建数据集](https://mintcdn.com/oumi/D0vKyXNqx2ohrLV9/images/datasets-create-options.jpg)

值得关注的点在于它和「调 API」是两种思路。租来的模型人人有份，能改的只有提示词；oumi 这套是把模型权重调成自己的，同样的任务靠模型本身适配，而不是靠堆提示词。对认真做 Agent、又不想被某一家模型厂商锁死的团队来说，这是一个能把训练、评测、部署全流程握在自己手里的选项，数据也不用出本地。
