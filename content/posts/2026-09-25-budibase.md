企业内部每天都有大量重复性操作：报销审批、工单流转、数据录入、报表汇总。过去几年，低代码平台把这些操作搬进了可视化界面，但活儿还是得靠人一个个点、一个个批。现在风向变了——低代码平台开始往系统里塞 AI Agent，让它们自己去动手。

这波转向里动作最彻底的一个，是 Budibase。这个开源低代码平台在 GitHub 上攒了 2.8 万 Star，最近直接把一句话定位改成了「AI Agents that run your operations」——让 AI Agent 来跑业务。

**项目地址：**https://github.com/Budibase/budibase

![Budibase 的 AI Agent 界面](https://res.cloudinary.com/daog6scxm/image/upload/v1775572268/github/Agent_preview.jpg)

Budibase 里的 Agent 不是那种只会陪聊的机器人。员工问问题、提审批、报故障时，Agent 能听懂请求，然后自己去执行：创建记录、路由审批、更新应用、通知相关团队。等于把原来「人手动操作」的环节，换成 Agent 自动跑起来的工作流。

![Budibase 的 Agent 执行动作](https://res.cloudinary.com/daog6scxm/image/upload/v1775572270/github/Agent_Actions.jpg)

另一个值得一提的点是「Model agnostic」——不绑定单一模型。Budibase 通过 LiteLLM 接入大模型，凡是 OpenAI 兼容的接口都能用，Mistral、Qwen、GPT-OSS、Llama 这类开源模型都可以，团队按隐私和成本自由选择。所有 Agent 还走角色权限控制，能碰哪些数据、能调哪些 API 由管理员说了算，不会越权乱跑。

![Budibase 的 Agent 对话界面](https://res.cloudinary.com/daog6scxm/image/upload/v1775573887/github/Agent_Chat.jpg)

装起来只要一条 Docker 命令，就能自托管：

```bash
docker run -d -t \
  --name=budibase \
  -p 10000:80 \
  -v /local/path/data:/data \
  --restart unless-stopped \
  budibase/budibase:latest
```

启动后浏览器打开 http://localhost:10000 就能用，不想自己维护也可以用官方的 Budibase Cloud。

这套东西适合谁？已经在用低代码平台搭内部工具、想把重复操作交给 AI Agent 的团队。低代码 + AI Agent 是不是最终形态还不好说，但「让 Agent 真正去执行操作」这个方向，正在成为内部工具平台的标配能力。
