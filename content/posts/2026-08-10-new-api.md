**大家好，我是雷达君。**

凌晨一点，你在笔记本前贴了四张便利贴。一张写着 OpenAI 的 API 格式，一张写着 Claude 的消息结构，一张是 Gemini 的调用参数，还有一张是你自己的转换脚本——已经改了第三版，还是没跑通。

你只是想同时用三个模型做 A/B 测试，结果写了一千多行“胶水代码”，全是格式转换、错误兼容、SDK 适配。真正发请求的逻辑，不到 200 行。

你以为换模型只是改一下`model`参数。实际上你得重写半套调用代码。更麻烦的是，团队里七八个人都在做同样的事——各自写各自的转换脚本，各自维护各自的 API Key，各自算各自的账单。

你需要的不只是一个“模型聚合工具”，而是一个**能统一管理所有 AI 资产、带完整计费和权限体系的生产级网关**。

今天雷达君要安利的这个开源项目，就是来填这个坑的。它基于经典项目 One API 二次开发，但**比 One API 多走了好几步**——支持更多模型格式互转、更完整的计费体系、更活跃的社区维护。

它就是——**New API**。

## 01 ｜核心逻辑：把全网大模型，塞进一个接口

New API 的核心理念用一句话就能说清楚：**不管你用哪家模型，我只认一套接口**。

OpenAI 有 OpenAI 的 API 格式，Claude 有 Claude 的消息格式，Gemini 有 Gemini 的调用方式。你想同时用三家，就得写三套代码、维护三套 SDK、处理三种不同的错误码。

New API 把所有这些差异全部抹平了。它在中间层做了一层**格式转换**——把 Claude Messages 转成 OpenAI 兼容，把 Gemini 转成 OpenAI 兼容，反过来也能转。你在上层永远只调一套 OpenAI 风格的接口，背后连的是哪个模型，对调用方完全透明。

更关键的是，它不止是“转发”，而是**完整的 AI 资产管理**。多渠道分组、加权随机分发、失败自动重试、用户级限流、Token 配额管理、在线充值——一个网关，把 AI 调用的所有脏活累活全包了。

**一句话：你只管调 API，剩下的路由、计费、权限、监控，New API 全帮你搞定。**

## 02 ｜硬核功能盘点

> 🔗 **GitHub 地址**：https://github.com/QuantumNous/new-api

### 1. 协议全家桶：OpenAI、Claude、Gemini 随意互转

这是 New API 最核心的能力，也是它和 One API 最大的不同。

One API 主要做 OpenAI 兼容的转发。New API 在此基础上做到了**三大协议双向互转**：

- **OpenAI Chat Completions ↔ Claude Messages**：你用 OpenAI 格式调 Claude，New API 帮你翻译
- **OpenAI → Google Gemini**：把 Gemini 封装成 OpenAI 接口
- **Google Gemini → OpenAI**：反过来也能转
- **OpenAI Responses**：支持最新的 Responses 格式
- **OpenAI Realtime API**：包括 Azure 的实时语音接口

你不需要为每个模型写不同的 SDK。一套代码，通吃所有模型。

### 2. 不只是文本：图像、音频、视频、Rerank 全支持

New API 的野心不止于聊天模型。它支持的接口类型覆盖了 AI 能力的方方面面：

- **图像生成**：支持 Midjourney-Proxy
- **音乐生成**：支持 Suno-API
- **音频转录/合成**：Whisper 转录、TTS 语音合成
- **Embedding**：向量嵌入接口
- **Rerank**：Cohere、Jina 的重排序模型

**一个网关，覆盖了从文本到图像到音频到视频的全链路 AI 能力。**

### 3. 智能路由：加权分发、自动重试、用户级限流

New API 内置了一套完整的企业级路由引擎：

- **加权随机分发**：给不同渠道设置权重，按比例分配流量
- **失败自动重试**：某个上游挂了，自动切到备用渠道
- **用户级模型限流**：每个 Token、每个用户可单独设置速率限制
- **渠道模型自动发现**：上游新增模型，网关自动识别

**你不是在“连模型”，你是在“建一个 AI 中台”。**

### 4. 完整的计费与权限体系

这是 New API 在企业场景里最“能打”的地方：

- **在线充值**：支持 EPay、Stripe 等支付通道
- **阶梯定价**：支持按量折扣、批量优惠
- **Token 分组管理**：不同 Token 绑定不同模型、不同配额
- **多语言界面**：简体中文、繁体中文、英文、法语、日语
- **数据看板**：用量统计、成本分析、可视化仪表盘

**你不需要自己写计费模块，不需要自己搭用户系统。New API 全给你配好了。**

### 5. 多种授权登录：Discord、Telegram、LinuxDO、OIDC

New API 支持**Discord、Telegram、LinuxDO、OIDC**等多种第三方授权登录方式。团队接入、社区运营、企业 SSO——你不需要自己搭一套用户注册体系，直接用现有账号登录就行。

### 6. 全格式兼容 + 灵活的部署方式

New API 支持 SQLite、MySQL、PostgreSQL 三种数据库，Docker 一键部署，也支持宝塔面板和 Electron 桌面应用。从个人开发者到企业级集群，全覆盖。

## 03 ｜ New API vs One API

既然 New API 是基于 One API 二次开发的，那它到底“新”在哪？

| 维度         | **New API**                                   | **One API**        |
| :----------- | :-------------------------------------------- | :----------------- |
| **协议支持** | OpenAI + Claude + Gemini **三方互转**         | 主要是 OpenAI 兼容 |
| **接口覆盖** | 文本 + 图像(Midjourney) + 音乐(Suno) + Rerank | 主要是文本         |
| **计费体系** | 阶梯定价 + 在线充值 + 按量折扣                | 基础定价           |
| **UI 界面**  | 全新设计，更现代化                            | 经典风格           |
| **授权登录** | Discord/Telegram/LinuxDO/OIDC                 | 基础               |
| **维护状态** | **活跃**（42K+ Star，持续更新）               | 较慢               |
| **开源协议** | AGPL-3.0                                      | MIT                |

**简单说：One API 是“轻量、宽松”的选项，New API 是“功能更全、更活跃”的增强版**。如果你需要 Midjourney、Suno、Claude/Gemini 互转、在线支付、阶梯定价——New API 是目前开源方案里最完整的选择。

## 04 ｜典型场景和避坑

**适合谁用？**

- **需要统一管理多个 AI 模型 API 的个人开发者/小团队**：一个网关管住所有模型，不用为每个模型写不同的调用代码
- **做 AI API 分发或中转服务的团队**：完整的计费、充值、限流、用户管理体系，开箱即用
- **企业内部需要做 AI 成本分摊的组织**：按 Token、按用户、按渠道的精细化成本核算
- **需要用 Midjourney、Suno 等非文本 AI 能力的开发者**：New API 把这些能力也统一成了 OpenAI 风格的接口

**不推荐给谁？**

- **只需要单模型简单调用的个人项目**：直接用官方 SDK 可能更轻量
- **对 AGPL-3.0 协议有合规顾虑的商业项目**：需注意 AGPL-3.0 的商用约束
- **追求 MIT 等宽松开源协议的团队**：可以继续使用 One API

## 05 ｜快速上手指南（2 分钟）

**第 1 步：Docker Compose 一键部署**

```bash
git clone https://github.com/QuantumNous/new-api.git
cd new-api
docker-compose up -d
```

**第 2 步：访问管理界面**
浏览器打开 `http://localhost:3000`，进入管理后台。

**第 3 步：配置上游模型**
在后台添加你需要的模型渠道——OpenAI、Claude、Gemini、DeepSeek、通义千问、Midjourney 等。

**第 4 步：生成 API Key**
创建 Token，绑定可用模型和配额，开始调用。

> **验证安装成功**：访问`http://localhost:3000`，如果能正常打开管理界面，说明安装成功。

## 06 ｜总结

OpenAI 说一套，Claude 说另一套，Gemini 又说一套。你想同时用三家，就得维护三套代码、三套 SDK、三套错误处理。New API 的答案是：**不管它们说什么，我只翻译成一种语言**。

基于 One API 二次开发但比 One API 多走了好几步——三方协议互转、Midjourney/Suno 支持、阶梯定价、在线充值、现代化 UI、活跃维护。它不是“又一个聚合工具”，而是一个**生产级的 AI 资产管理网关**。
