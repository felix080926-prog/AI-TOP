AI Agent 越做越多，但大多没有记忆。今天聊过的偏好，换个会话就忘了；用户第三次解释同一个需求，助手还是一脸茫然。

常见的做法是把历史对话一股脑塞进上下文窗口。代价很直接——token 消耗上去了，检索精度下来了，对话越长越容易把重点淹没在噪音里。

有个开源项目换了一种思路：不在上下文里堆历史，而是单独做一层记忆。它叫 mem0（读作 mem-zero），是目前这个方向上最受关注的项目之一，已经攒了 6.8 万 Star，今天一天又涨了 538，Apache-2.0 协议，出自 Y Combinator S24 团队。

![Mem0 项目主图](https://raw.githubusercontent.com/mem0ai/mem0/main/docs/images/banner-sm.png)

**项目地址：** https://github.com/mem0ai/mem0

## 它到底改了哪一步

2026 年 4 月，mem0 换了一套新的记忆算法。

提取环节从「增删改查」简化成单次 ADD-only——一次 LLM 调用把值得记的东西抽出来，不做 UPDATE 也不做 DELETE。记忆只累积、不覆盖，避免了过去那种新记忆把旧事实改错的问题。

检索环节改成多信号并行：语义向量、BM25 关键词、实体匹配三条路各打各的分，最后融合排序。

再加一层时间推理，回答「现在住哪」这类问题时，能挑出时间点上正确的那一条，而不是最相似的那一条。

![Mem0 记忆层在 Agent 技术栈里的位置](https://raw.githubusercontent.com/mem0ai/mem0/main/docs/images/memory-agent-stack.png)

效果写在 README 里，评测框架也一起开源了：LoCoMo 从 71.4 提到 92.5，LongMemEval 从 67.8 提到 94.4，1M token 规模的 BEAM 拿到 64.1。单次检索约 7K token，p50 延迟 1 秒上下。

官方也标注了：这些分数跑在托管平台上，含开源 SDK 里没有的优化，开源用户拿到的提升方向一致、数值不会完全一样。

![Mem0 的记忆提取与检索流程](https://raw.githubusercontent.com/mem0ai/mem0/main/docs/images/memory-extraction.png)

## 装起来只要几步

最轻的是库模式：

```bash
pip install mem0ai
```

在自己机器上跑完整服务，进 server 目录一条命令起栈、建管理员、发第一个 API Key：

```bash
cd server && make bootstrap
```

手动方式则是 `docker compose up -d`，默认在 http://localhost:3000 起管理界面。

只想在终端里试，装 CLI（`npm install -g @mem0/cli` 或 `pip install mem0-cli`）后：

```bash
mem0 init
mem0 add "Prefers dark mode and vim keybindings" --user-id alice
mem0 search "What does Alice prefer?" --user-id alice
```

## 适合谁用

做客服机器人、长期陪伴型助手，或者任何需要跨会话记住用户的产品，都可以把它当成一层基础设施接进去。库模式适合做原型，自托管适合有自己基础设施的团队。

它不解决模型本身的能力问题，也不适合一次性问答——如果每次对话本来就互不相关，加一层记忆只是多花 token。
