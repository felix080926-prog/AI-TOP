AI 编程助手越来越强，但一个老问题一直没解决：需求只活在聊天记录里。说一句"加个暗黑模式"，它可能理解偏了，或者顺手把无关组件也改了。代码能跑，却跟真正要的需求对不上，改起来又是新一轮拉扯。

OpenSpec 就是冲着这个问题来的。它做的事很直白：在 AI 动手写代码之前，先让人和 AI 一起，把"到底要建什么"用一份结构化规格（spec）定下来。这个思路有个名字——Spec-Driven Development，规格驱动开发。

**项目地址：** https://github.com/Fission-AI/OpenSpec

![OpenSpec 仪表盘预览](https://raw.githubusercontent.com/Fission-AI/OpenSpec/HEAD/assets/openspec_dashboard.png)

它跟别家重量级方案不一样。有些工具一上来就是一堆阶段门禁，proposal 过了才能进 design，design 过了才能写 tasks，流程像审批。OpenSpec 走的是"fluid not rigid"（灵活而非僵化）：每个变更就是一个文件夹，里面放着 proposal.md（为什么做、改什么）、specs/（需求和场景）、design.md（技术方案）、tasks.md（实施清单）。这些文件都是普通 Markdown，没有特殊语法要学；AI 写、人审，哪一步不满意随时改，没有硬性门槛。

最好用的地方，是跟 AI 助手配合的方式。装好后，直接在 Claude Code、Cursor、Codex 这些工具里敲斜杠命令：`/opsx:propose add-dark-mode`，AI 自动生成上面那套文件；确认没问题再敲 `/opsx:apply`，它照着规格一条条实现；做完 `/opsx:archive` 归档。等于给 AI 套了根缰绳——先交方案、人点头再动手，而不是"说一句它糊一段"。

![OpenSpec 主视觉](https://raw.githubusercontent.com/Fission-AI/OpenSpec/HEAD/assets/openspec_bg.png)

装起来只要几步。需要 Node.js 20.19.0 以上，全局装 CLI：

```bash
npm install -g @fission-ai/openspec@latest
# macOS / Linux 也可以用 Homebrew
brew install openspec
```

进项目目录初始化：

```bash
cd your-project
openspec init
```

之后就能在支持的 AI 工具里用斜杠命令了。它支持 30 多个 AI 助手，Cursor、Claude Code、GitHub Copilot、Codex、Amazon Q 都在列，不同工具的斜杠拼写略有差别，`openspec init` 会给出对应写法。

从数据看热度不低：仓库已经攒了 6.9 万多 Star，今天一天就涨了 700 多，挂在 GitHub Trending 前列。MIT 协议，社区叫它"the most loved spec framework"（最受喜爱的规格框架）。

它更适合谁？团队协作最吃香——尤其一个功能横跨后端、前端、公共库的，OpenSpec 的 Stores（规划独立仓库）能让全团队和每个 coding agent 读同一份规格，而不是各改各的 wiki。个人开发也用得上：单仓库里靠它管住 AI，别写歪。反过来，如果只想让 AI 补个小脚本，这份"先写规格"的仪式感就有点重。

客观说，规格驱动不是人人都买账，争议在于"规格会不会很快过时、是不是又多了一堆要维护的文档"。但 OpenSpec 至少把这件事做到了轻量、可迭代。愿不愿意用，装完跑一遍 `/opsx:propose`，心里就有数了。
