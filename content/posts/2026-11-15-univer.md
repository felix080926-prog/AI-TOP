11 月 14 日，Univer 发布了 1.5.0 版本。第二天，这个仓库出现在 GitHub Trending 榜单上，单日新增 495 星，总星数停在 2.5 万附近。一个做「办公 SDK」的项目在这个时间点被重新盯上，背后其实是 AI Agent 圈子里一个没解决的老问题。

![Univer Office SDK](https://raw.githubusercontent.com/dream-num/univer/HEAD/docs/img/readme/hero-banner.png)

## Agent 会推理，但不会办公

Agent 能写代码、能查资料、能调接口，可一碰到表格和文档就开始露怯。原因很朴素：Office 文件是给人看的，行列、样式、公式、批注层层嵌套，模型读不进去、改不安全，改完也没法自己验证。

于是「给 Agent 配一个能读、能写、能自查的办公运行时」成了新方向。Univer 团队把这套东西叫 Office Harness——不是又一个在线表格，而是 Agent 干活时踩的那块地板：数据可寻址、改动可版本化、结果能渲染出来看一眼。

Univer 是 Luckysheet 的官方继任者。作者刘洋当年业余时间写出 Luckysheet，后来去飞书做电子表格技术负责人，2023 年出来创业成立梦数科技，把整套架构推倒重做，才有了 Univer。仓库 2022 年 9 月开源，Apache-2.0。

**项目地址：**https://github.com/dream-num/univer

## 1.5.0 更新了什么

这次版本的重点在图表和计算：新增「图表工作表」，图表可以独占一个标签页，源数据仍留在普通工作表里，还能在表之间搬动并支持撤销重做；补齐堆叠折线图、百分比堆叠折线图，以及柱状、条形、折线、散点图的分系列误差线；公式计算过程的内存占用下降；Pro 免费版覆盖了更多编辑和本地输出流程。

![Univer 表格编辑器](https://raw.githubusercontent.com/dream-num/univer/HEAD/docs/img/readme/cards/sheets.webp)

边界需要说清楚。仓库开源的是 Web SDK 的核心架构与引擎：内容模型、插件与命令系统、公式引擎、渲染引擎、Facade API，以及表格和文档的编辑能力。XLSX/DOCX/PPTX 导入导出、多人实时协同、图表、透视表这些，属于单独授权分发的 Server SDK 和商业插件，评估版带水印和功能限制。官网功能对比表可以按「只看开源」筛一遍，选型前值得核一次。

## 装起来只要两条命令

在 Vite 这类前端工程里，开源部分不需要任何商业授权：

```bash
pnpm add @univerjs/presets @univerjs/preset-sheets-core
```

页面里放一个有高度的容器，再初始化：

```ts
import { createUniver, LocaleType, mergeLocales } from '@univerjs/presets'
import { UniverSheetsCorePreset } from '@univerjs/preset-sheets-core'
import UniverPresetSheetsCoreEnUS from '@univerjs/preset-sheets-core/locales/en-US'
import '@univerjs/preset-sheets-core/lib/index.css'

const { univerAPI } = createUniver({
  locale: LocaleType.EN_US,
  locales: { [LocaleType.EN_US]: mergeLocales(UniverPresetSheetsCoreEnUS) },
  presets: [UniverSheetsCorePreset({ container: 'app' })],
})

univerAPI.createWorkbook({})
```

想直接交给 Agent 用，官方另有一个 Univer CLI：在支持的编码 Agent 里执行 `npx skills add dream-num/skills -s univer-cli -g` 装上技能，之后描述想要的结果即可。要跑仓库本身，需要 Node.js 22.18 以上，`git clone` 之后 `pnpm install`、`pnpm dev`。

## 为什么值得关注

如果需求只是批量读写 Excel，openpyxl 或 LibreOffice 无头模式更轻，不必绕这一圈。Univer 的价值出现在另一种场景：人看到的编辑界面和 Agent 操作的数据模型必须是同一份。Agent 写完公式能重算，改完能渲染自查，人能在浏览器里复审再决定合并还是丢弃——这种「同一份文档、两种使用者」的结构，开源里完整选项并不多。

团队背景和 Luckysheet 的积累是加分项，商业层的边界与授权状态则是引入前必须自己确认的前提。
