大家好，我是雷达君。

深夜十一点，你合上那台用了五年的老旧笔记本，屏幕还亮着最后一个页面——上面是某大模型的官方配置要求：“推荐显存 16GB 以上，建议使用 A100 或 H100 GPU。”

你算了一下，光是搭一套能跑这个模型的硬件，就得花掉你三个月工资。

然后你在 GitHub 上翻到了一个项目。它用 C++写成，没有任何外部依赖，甚至能在你手里这台老掉牙的笔记本上跑起来。你半信半疑地敲了几行命令，十分钟后，一个 70 亿参数的大模型在你那台连独显都没有的电脑上开始流畅地生成文字了。

这个项目，就是**llama.cpp**。

## 01 ｜一个“叛逆”的决定

2023 年初，Georgi Gerganov 做了一个反潮流的决定。

当时的大模型推理，默认路径是“用 Python + PyTorch + 高端 GPU”。模型越大，需要的 GPU 越贵。所有人都默认：要跑大模型，就得有顶级硬件。

Gerganov 不这么认为。他决定用纯 C/C++重新实现 LLaMA 模型的推理逻辑，不依赖任何第三方库——没有 PyTorch，没有 TensorFlow，连 Python 都不需要。

他说：**大模型推理应该能在任何设备上运行——哪怕你没有 GPU，哪怕你用的是五年前的笔记本，哪怕你只有 4GB 内存。**

这个决定在当时看起来近乎疯狂。但三年后的今天，llama.cpp 已经是全球最广泛使用的开源 LLM 推理引擎之一。

## 02 ｜ 125K Star 的含金量

> 🔗 GitHub 地址：https://github.com/ggml-org/llama.cpp

GitHub 上，llama.cpp 已经攒下了超过**12.5 万颗 Star**，**超过 1700 名贡献者**参与过代码提交。

这个数字意味着什么？在 AI 开源项目里，它仅次于 AutoGPT 和 Stable Diffusion，是 GitHub 历史上 Star 数最高的项目之一。几乎每一个做本地 AI 推理的开发者，都直接或间接地用过它。

它是**GGUF 格式的创造者和定义者**。GGUF（GPT-Generated Unified Format）是一种专门为 LLM 设计的量化模型格式，通过 1.5-bit 到 8-bit 的整数量化，大幅降低模型体积和推理时的内存占用，让大模型能在普通硬件上运行。

这个格式已经成为整个行业的量化模型标准。

## 03 ｜为什么 llama.cpp 这么能打？

打开 llama.cpp 的文档，你会看到一长串“支持”列表——但它厉害的地方不在于“支持多少”，而在于**把“支持”这件事做到了极致**。

**它能在任何硬件上跑。**

苹果芯片是第一优先支持的对象。通过 ARM NEON、Accelerate 和 Metal 框架，llama.cpp 在 M 系列芯片上的推理性能接近原生。NVIDIA GPU 有定制 CUDA 内核，AMD GPU 有 HIP 后端，Intel GPU 有 SYCL，甚至连华为的昇腾 NPU 都有 CANN 后端。

**它支持 CPU 和 GPU 混合推理**。如果你的模型比显存大，它可以让一部分层在 GPU 上跑、一部分在 CPU 上跑，充分利用所有计算资源。

**它支持推测解码（Speculative Decoding）** 。用一个小的“草稿模型”先生成候选 token，再用大模型并行验证——推理速度能提升**1.5 到 2 倍**。

**它还支持多模态模型**。LLaVA、Qwen2-VL 这些能“看图说话”的视觉语言模型，llama.cpp 都原生支持。

## 04 ｜改变行业的三个贡献

**第一，它定义了 GGUF 格式。**

在 llama.cpp 之前，每个模型都有自己的格式，量化方案五花八门。llama.cpp 提出了 GGUF，一个统一的、高效的量化模型格式。现在，Hugging Face 上几乎所有开源模型都提供 GGUF 版本。

**第二，它让“本地运行大模型”成为了可能。**

在 llama.cpp 之前，“本地跑大模型”是极客的专利。llama.cpp 之后，任何有电脑的人都能做到。LM Studio、Ollama、Jan、text-generation-webui——这些你熟悉的本地 AI 工具，底层都在用 llama.cpp。

**第三，它改变了 AI 推理的“默认路径”。**

当整个行业都在说“跑大模型需要高端 GPU”的时候，llama.cpp 证明了另一条路是可行的——纯 CPU 推理、低内存占用、跨平台支持。这条路让 AI 从云端走向了桌面、走向了笔记本、走向了手机。

## 05 ｜怎么上手？

llama.cpp 提供了多种使用方式：

**方式一：直接访问 llama.app**

最简单的入门方式，不需要安装任何东西。

**方式二：下载预编译二进制**

从 GitHub Releases 页面下载对应平台的二进制文件，解压即用。

**方式三：Docker 运行**

```bash
docker run -it ghcr.io/ggml-org/llama.cpp:latest
```

**方式四：从源码编译**

```bash
git clone https://github.com/ggml-org/llama.cpp
cd llama.cpp
mkdir build && cd build
cmake ..
make -j
```

安装完成后，一行命令就能跑起来：

```bash
# 从Hugging Face直接下载并运行
llama-cli -hf ggml-org/gemma-3-1b-it-GGUF

# 或者使用本地GGUF文件
llama-cli -m my_model.gguf -p "Hello, world!"
```

还可以启动一个 OpenAI 兼容的 API 服务器：

```bash
llama-serve -hf ggml-org/Qwen3.5-0.8B-GGUF
```

## 06 ｜总结

三年过去了，那个“让大模型在破烂电脑上也能跑”的叛逆想法，已经变成了一个**12.5 万 Star、1900+贡献者、定义了行业标准**的传奇项目。

llama.cpp 没有发明大模型，但它**让大模型从云端走进了每个人的电脑**。它证明了：技术普惠，不是等硬件降价，而是把软件做到极致。
