大模型本地部署的痛点，说来说去就那么几个：显存不够、速度太慢、配置太复杂。想在消费级显卡上跑一个 70B 的模型，通常得靠量化、蒸馏、剪枝三件套，精度掉一截不说，能跑多大的模型也早被显存卡死了上限。

AirLLM 换了一条完全不同的路：它不压缩模型，而是把模型「拆开」来加载。推理时只把当前需要的那一层放进显存——对 MoE 模型，则只放进当前 token 实际路由到的那几个专家——其余的全部留在内存或硬盘里，用到哪读到哪。于是显存需求不再取决于模型总大小，只取决于单层的大小。

**项目地址：**https://github.com/lyogavin/airllm

这个思路带来的数字相当夸张。目前最大的开源模型 Kimi K3（2.8 万亿参数），AirLLM 能在一张 RTX 6000 Ada 上以 3.72GB 的显存峰值端到端跑起来，而不用租整台数据中心。DeepSeek-V3（671B）压在约 12GB，Llama 3.1 405B 压在 8GB，Qwen3.8-Flash-Next（125B）压在 6GB。对显存只有 4GB 的入门卡来说，这几乎是唯一能碰这些超大模型的开源方案。

不过要把话讲清楚：它跑得快吗？不快。这是用磁盘换显存，瓶颈从显存转移到了 I/O。项目自己测得 Kimi K3 的生成速度大约 292 秒一个 token，属于可行性验证级别，不是生产配置。对个人开发者和小团队来说，它更适合用来试模型、做研究、跑边缘实验，而不是上线服务。

装起来只要一条命令：

```
pip install airllm
```

然后一行代码就能加载任意主流开源模型：

```python
from airllm import AutoModel
model = AutoModel.from_pretrained("Qwen/Qwen3-32B")
```

Llama、Qwen、DeepSeek、Mistral、Phi、Gemma、Kimi K3 这些主流家族基本开箱即用，新模型发布当天往往就跟上支持。想要进一步提速，还有可选的 4/8 bit 块级量化，能带来最多 3 倍的速度提升，精度损失几乎可忽略。

它真正解决的是一个被大多数人默认接受的问题——「大模型就得配大显存」。方向本身很有意义，它把「能不能跑」的门槛压到了极低，让普通显卡也有了碰超大模型的机会。适合手头只有小显存、又想亲手验证大模型能力的开发者；至于追求吞吐的线上服务，还是老老实实上多卡或者云推理更靠谱。
