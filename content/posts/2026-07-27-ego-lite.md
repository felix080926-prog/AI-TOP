**大家好，我是雷达君。**

你有没有经历过这样的崩溃瞬间：你让 Claude Code 帮你订一张机票，它说"请先登录"；你让 Codex 帮你查银行流水，它弹出一个验证码页面然后卡住不动；你花半小时给 AI Agent 配好了 Selenium + headless Chrome，结果一跑发现所有网站的 Cookie 全丢了，登录状态归零，Agent 和你在同一个浏览器里抢标签页，一个不小心就把你的工作台搞得天翻地覆。

这不是你的问题。整个 AI Agent 生态在过去一年里爆发式增长，模型越来越聪明、工具链越来越丰富，但最底层的问题——"浏览器怎么给 AI 用"——始终没有解决好。现有的方案无非两条路：要么用 Puppeteer/Playwright 开一个裸浏览器，从头登录，效率低下；要么用 browser-use 这类框架驱动一个独立实例，配置繁琐且登录态很难打通。你和你自己的 AI Agent，共用一台电脑，却像两个陌生人。

而今天要讲的 **ego-lite**，来自 citrolabs，用一种极其优雅的方式解决了这个问题：它重新设计了一个浏览器，从底层架构上把"你的浏览"和"Agent 的浏览"分成了两个完全隔离的平行世界。你在前台正常刷网页，Agent 在后台自己的 Space 里跑自动化任务，两人互不干扰，共享同一套登录态。更关键的是——零成本，零配置。

## 01 ｜核心逻辑

ego-lite 的设计哲学可以用一句话概括：**不是给 Agent 一个浏览器，而是让 Agent 和你共享同一个浏览器。** 这个看似微小的区别，决定了整个架构。

传统的浏览器自动化方案（browser-use、agent-browser 等）本质上是"自动化框架"——它们没有自己的浏览器，需要驱动一个外部浏览器实例。这带来了三个致命问题：第一，Agent 的浏览器是裸的，没有你的 Cookie、密码、书签，每个网站都要重新登录；第二，Agent 和你的浏览器是两个独立进程，无法共享状态；第三，你需要额外安装和配置一堆依赖，光是让 Selenium 跑起来就可能耗掉一个下午。

ego-lite 的做法完全不同。它自己就是一个完整的浏览器（基于 Chromium 深度定制），安装后可以直接选择从你现有的 Chrome 迁移数据——登录态、Cookie、密码、书签、扩展插件，一键全部继承。然后，它为每一个 AI Agent 分配一个独立的"Space"——可以理解为一个完全隔离的浏览沙盒。Agent 在自己的 Space 里操作网页时，用的是你的登录态，但操作完全在你的视线之外、不影响你当前的标签页。

更巧妙的是它的通信层。ego-lite 没有走传统的 CLI 路径（Agent 发一个命令、等结果、再发下一个），而是把浏览器的能力封装成一组 JavaScript 函数直接暴露给 Agent。Agent 要做的是"写代码"：它写一段 JavaScript 调用 snapshot、fill、click、wait、navigate、capture 等工具函数，ego-browser 在页面里一次性执行完，把结果打包返回。这意味着一个复杂的多步骤任务，Agent 可以在一次代码输出里完成，而不需要陷入"发两个命令→看结果→再发两个命令"的低效循环。基准测试显示，复杂任务的速度最多提升 2.5 倍，token 消耗显著下降。

## 02 ｜硬核功能盘点

>  🔗 GitHub 地址：https://github.com/citrolabs/ego-lite

- **独立 Space，多 Agent 并行**：每个 AI Agent（或每个任务）获得一个完全隔离的 Space。你可以让 Claude Code 在 10 个 Space 里同时处理 10 条销售线索，让 Codex 在另外 5 个 Space 里抓取竞品网站数据。所有 Space 在同一浏览器内并行运行，互不干扰，你的鼠标和键盘完全不受影响。

- **一键 Chrome 数据迁移**：首次启动时，ego-lite 会询问是否迁移 Chrome 数据。选"是"，你的所有登录态、Cookie、密码、扩展和书签都会被继承。Agent 从此不再需要"先登录"——它天然就带着你的身份在工作。

- **Code-base 而非 CLI-base**：这是 ego-lite 最核心的性能优势。Agent 不是通过命令行逐条操作，而是直接写 JavaScript 代码调用浏览器 API。复杂工作流可以在一次调用中完成，实测速度比 CLI 方案快 2.5 倍，token 消耗大幅降低。

- **内核级页面快照（Snapshot）**：ego-lite 对 Chromium 做了内核层面的定制，产出的页面快照质量在同类产品中最强。它能可靠处理深层嵌套 iframe、动态加载内容等极端情况——而这些恰恰是 browser-use 等方案经常翻车的地方。

- **全 Agent 兼容**：通过 ego-browser 这一连接层，Claude Code、Codex、Cursor 以及任何自定义 Agent CLI 都能驱动 ego-lite。它不绑定任何一个 AI 平台，你用什么 Agent，它就服务什么 Agent。

- **经验积累系统（即将上线）**：Agent 在浏览器任务上最耗时的是试错。ego-lite 的官方 Skill 会将每次成功的操作用法沉淀为可复用的工具和工作流，类似任务后续最多提速 5 倍。这是一个"越用越快"的正循环。

## 03 ｜典型场景和避坑

**典型场景一：批量数据采集与富集**

假设你要从 20 个竞品网站抓取产品信息，并在 CRM 系统中补充对应的联系人数据。用传统方案，你需要为每个网站写爬虫、处理登录、应对反爬。用 ego-lite：在 Agent CLI 中输入任务描述，Agent 自动在多个并行 Space 中同时抓取，你的登录态天然带入，大部分网站的认证门槛直接消失。一个原本需要半天的工作，半小时内完成。

**典型场景二：日常自动化流程编排**

每周一早上你要登录 5 个内部系统导出报表、汇总到飞书表格。这是一个典型的重复性多步骤任务。ego-lite 的 Code-base 模式允许 Agent 一次性写完整个流程的 JavaScript，在所有 Space 中并行执行。你甚至不需要守在电脑前——Agent 在后台独立完成任务，你在前台继续自己的工作。

**避坑指南**

- 第一，ego-lite 目前仅支持 macOS。如果你用的是 Windows 或 Linux，需要等待官方后续支持（已在路线图中）。建议关注项目的 GitHub Issues 和 Discussions 跟踪进展。

- 第二，Chrome 数据迁移是一把双刃剑。虽然它极大降低了 Agent 的登录门槛，但也意味着 Agent 拥有和你一样的权限。如果你在迁移时选了"是"，确保你的 Agent 任务是可信的，不要在公开的 Agent 配置中暴露敏感 Cookie。

- 第三，Space 的并行数量受限于你的机器性能。虽然 ego-lite 很轻量，但如果你同时开 50 个 Space 跑复杂 JS，CPU 和内存压力会明显上升。建议根据实际硬件情况，从 5-10 个 Space 起步，逐步扩展。

## 04 ｜上手教程

ego-lite 的安装异常简单。以下三种方式任选其一：

**方式一：直接下载 macOS App**

访问 [ego-lite GitHub Releases](https://github.com/citrolabs/ego-lite) 下载最新的 macOS 安装包，双击安装即可。安装完成后，ego-browser skill 会自动添加到所有 Agent 的 skills 目录中。

**方式二：通过 npx 安装 skill**

```bash
npx skills add citrolabs/ego-lite
```

第一次跑浏览器任务时，Agent 会引导你完成 ego-lite 本体安装。

**方式三：让 Agent 自己装**

直接把下面这句话发给你的 Agent：

```
Set up ego lite for me: https://github.com/citrolabs/ego-lite
Read `skills/ego-browser/references/install.md` and follow the steps to install ego lite.
```

Agent 会阅读安装文档并自主完成全部配置流程。

首次启动时会弹出一个选择：是否迁移 Chrome 数据。推荐选"是"——你的登录态和书签会无缝继承到 Agent 的工作环境。

安装完成后，在 Agent CLI 中输入：

```
/ego-browser follow @ego_agent on x.com for me
```

Agent 会自动在独立的 Space 中打开页面、读取快照、执行操作、返回结果——全程不影响你的浏览。

## 05 ｜总结

ego-lite 并不是一个"又一个浏览器自动化工具"。它解决的问题层面前所未有地精准：AI Agent 需要一个浏览器，但不应该和你的浏览器打架。过去我们一直在用 2020 年的工具（Selenium、Puppeteer）解决 2026 年的问题（AI Agent），ego-lite 终于把浏览器的设计出发点上移了一层，从"给人用的浏览器"变成了"人和 Agent 共享的浏览器"。

当然，它还有明显的局限：macOS only 目前阻挡了大部分用户，Windows/Linux 的支持时间表也尚未明确；经验积累系统还在路上，还没到"开箱即用"的完整体验。但作为一个开源且免费的项目，它在不到两个月内拿下 4.7K Star、日均增长近千星的速度，已经说明社区对这个方向的认可。

如果你正在用 Claude Code、Codex 或 Cursor 做任何涉及浏览器的自动化任务，ego-lite 值得你花 10 分钟试一下。它可能不是最终答案，但一定是通往答案的最短路径。
