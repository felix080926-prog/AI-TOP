大模型写代码有个绕不开的毛病：训练数据停在某个时间点，而框架和库的 API 几乎每天都在变。让它写 Next.js，它给你吐出两年前的路由写法；让它写 React Query，它编一个根本不存在的 hook；让它写 Supabase，它信心十足地调用一个早就改名的函数。模型越自信，翻车越彻底。

这个问题最朴素的解法，是别让模型靠记忆，直接把它正在用的那个库的最新文档塞进上下文里。Upstash 开源的 Context7 干的就是这件事——一个给 LLM 和 AI 代码编辑器用的文档管道，从官方源码里抽出带版本号的文档和代码示例，实时放进你的 prompt。

**项目地址：**https://github.com/upstash/context7

![Context7 项目封面](https://raw.githubusercontent.com/upstash/context7/master/public/cover.png)

它解决的其实不是笼统的「文档过时」，而是「幻觉 API」这个更具体的问题。大模型编出来的 API 往往看起来完全合理——参数名对、类型对，只有这个函数压根不存在。Context7 的做法是把真实、带版本号的文档直接放进上下文，模型照着真实签名写，就没有了瞎编的空间。它在 MCP.Directory 上长期排第一，ThoughtWorks 2025 年 11 月的技术雷达把它放进「Trial」环，GitHub 上已经攒了 6.2 万 Star，今天一天又涨了 788。

另一个值得说的是它最近把架构重做了一遍。以前是让模型一遍遍调 MCP 去搜、去筛文档，来回好几轮，token 烧得多还不一定选得准；现在把筛选和排序挪到了服务端，用快速重排模型先把最相关的那几段挑出来，只把真正有用的部分回给模型。官方说 token 用量降了 65%，延迟降了 38%。对使用者来说，最直观的变化就是快，而且上下文里没那么多噪音。

![Context7 官方文档概览](https://context7.com/docs/og/overview.png)

装起来只有一条命令，前提是装了 Node.js 18 以上：

```bash
npx ctx7 setup
```

它会走 OAuth 授权、生成 API key，然后按你选的模式装好对应的 skill 或 MCP 配置，可以用 `--cursor`、`--claude`、`--opencode` 指定目标工具。想手动走 MCP 的话，服务器地址是 `https://mcp.context7.com/mcp`，配上 API key 就行。装完以后，在提示词里加一句「use context7」，它就会在需要查库文档时自动去拉最新说明。CLI 也给了两个直白的命令：`ctx7 library <名字> <问题>` 先定位库，`ctx7 docs <库ID> <问题>` 再取文档。

Context7 适合每天跟 AI 编程助手配合、又经常碰那些迭代很快的框架的人——Next.js、React Query、Supabase、Prisma 这类版本号一年跳好几次的库，效果最明显。它不是让你换个模型，而是给现有模型补上一个外部知识管道，所以跟 Cursor、Claude Code、Codex、Windsurf 都能搭。反过来，如果你写的是内部私有库、文档没有公开索引，那它帮不上忙，得靠它的企业版把整套栈部署到内网。免费版有 API key 额度限制，重度使用可以到 context7.com/dashboard 领一个免费 key 提额。
