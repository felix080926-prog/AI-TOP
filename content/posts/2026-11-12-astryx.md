这两天 GitHub Trending 上，一个设计系统连着四天挂在榜上。Meta 内部用了八年的设计系统 Astryx，11 月 8 日登上 GitHub TypeScript 日榜第一，当天涨了 863 星；之后几天的单日增量一路放大——1,793、3,278、3,108，到 11 月 12 日总 Star 已经到 2.5 万。

一个设计系统能冲上榜首，本身就说明点问题——它不是给人用的那种设计系统。

## 设计系统的「用户」变了

传统设计系统的消费者是设计师和前端工程师：出规范、出组件库、写文档，人去看、人去用。但这两年写代码的主力里混进了 AI Agent，Claude Code、Codex、Cursor 这类工具接手了越来越多的界面代码。

问题随之而来：Agent 不认识你的组件库。它只能凭训练数据猜一个按钮长什么样，猜出来的东西能跑，但和项目里其他页面对不上。想让它按规范写，它也没处查规范。

Astryx 的特别之处在于，它从第一天就把 Agent 当成一等用户来设计，而不是事后给一套现成的设计系统打补丁。

> 🔗 **项目地址：https://github.com/meta/astryx**

![Astryx 官方 Banner](https://astryx.atmeta.com/images/Astryx-Banner.png)

## 它到底做了什么

Astryx 在 Meta 内部长了八年，是公司里规模最大、用得最广的设计系统，支撑着 13,000 多个应用。开源出来的版本基于 React 19 和 StyleX，包含 150 多个无障碍组件、品牌级主题、深色模式、开箱即用的模板，以及一套命令行工具，MIT 协议，目前是 Beta。

对 Agent 的适配落在三件事上：CLI、MCP，以及写进项目根目录的 AGENTS.md。跑一条初始化命令，Astryx 会把组件索引、模板、设计 token 写进 AGENTS.md 或 CLAUDE.md——Agent 打开项目就能查到有哪些组件、每个组件怎么调，不用再猜。CLI 里还有 `astryx component Button` 这种用法，可以直接把某个组件的完整文档喂给模型。

![Astryx 的设计 token](https://raw.githubusercontent.com/meta/astryx/main/apps/docsite/public/FoundationsColors.png)

这带来一个挺实际的变化：Agent 产出的不再是「只能看的 HTML 原型」，而是能直接接进项目的 React 代码。官方文档里就有让 Agent 用 Astryx 从零搭一个产品页的示例，最后交付的是能直接接入的组件代码。

对人不算苛刻。样式没有被锁死——虽然 Astryx 自己用 StyleX 写样式，但用 Tailwind、CSS Modules 或原生 CSS 都能通过 className 覆盖。主题就是一组 CSS 自定义属性，改颜色、字体、圆角、动效都在 token 层完成，不用 fork 组件源码；真想改内部实现，`swizzle` 能把组件源码整个吐进你的项目。另外自带七套现成主题：neutral、butter、chocolate、matcha、stone、gothic、y2k。

## 装起来只要两条命令

React 19 及以上：

```bash
npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex
npm install -D @astryxdesign/cli
```

想让每个项目里的 Agent 都认得 Astryx，把 CLI 装到全局，再在项目里初始化一次：

```bash
npm i -g @astryxdesign/cli
npx @astryxdesign/cli init
```

`init` 写完 AGENTS.md 之后，Agent 就知道去 CLI 里查组件文档了。不需要 build 插件，也不用额外引入样式库。

![Astryx 的 CLI 集成](https://raw.githubusercontent.com/meta/astryx/main/apps/docsite/public/blog/astryx-v0-7-0/cli-integration.webp)

## 为什么值得关注

设计系统这个品类，过去十年解决的问题是「怎么让一群人和一个品牌保持一致」。现在多了一类新的贡献者：Agent。它不读文档、不看 Figma，只认上下文里能拿到的东西。

Astryx 给出的答案是：把规范做成机器可读的接口。这个思路会不会成为行业默认还不好说，但它至少指出了一件事——以后评价一个设计系统，除了组件好不好用，还得看它对 Agent 友不友好。

它现在还在 Beta，组件成熟度和生态都需要时间验证。但如果团队已经在用 Claude Code 或 Codex 写前端，这类「为 Agent 准备的设计规范」值得提前了解一下。
