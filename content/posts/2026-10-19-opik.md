大模型应用上线后最怕的不是报错，是它悄悄变烂了你还不知道。一段 RAG 检索召回错了、一个 Agent 多绕了几步工具调用、一次 Prompt 改动让幻觉率翻倍——这些黑盒内部的变化，光看最终输出根本发现不了。业界管这叫「LLM 应用的可观测性」，也是从 Demo 走向生产最容易被跳过、却最先翻车的一环。

GitHub 上 comet-ml/opik 就是冲着这个来的。它做的是 LLM 应用、RAG 系统和 Agent 工作流的全链路追踪与评测：把每一次模型调用、每一步工具调用、每一段检索都记下来摊开看，再配上一套自动化评测和生产级仪表盘，等于给黑盒装了个行车记录仪。

**项目地址：**https://github.com/comet-ml/opik

![Opik 平台主界面](https://raw.githubusercontent.com/comet-ml/opik/HEAD/readme-thumbnail-new.png)

先看它最核心的追踪能力。Opik 的 trace 细到能钻进 Agent 的每一次工具调用和 RAG 的每一段召回，一条 trace 树把整个调用链铺开，哪一环掉链子一眼就能定位，不用再靠猜。定位也很明确：不是给你一个玩具 demo，而是按生产规模设计的——官方说法是单日可处理 4000 万+ trace，还内置了 60 多个框架的原生集成，Google ADK、Autogen、Flowise 这些都在支持列表里。

![Opik 的 LLM 全链路追踪视图](https://www.comet.com/site/wp-content/uploads/2026/05/opik-llm-tracing.png)

除了追踪，更实用的是「评测」这一层。它自带幻觉检测、相关性、召回精度等 LLM-as-a-judge 指标，改完 Prompt 之后能直接对比前后效果，不再靠手动抽检。它甚至能把评测接进 CI/CD——用 PyTest 集成，让 LLM 流水线在每次提交时都跑一遍测试。这一点对团队意义很大：模型应用从此有了可回归的测试基线，而不是每次上线都提心吊胆。

![Opik 生产监控仪表盘](https://www.comet.com/site/wp-content/uploads/2026/04/opik-dashboards-1.png)

### 上手就两条命令

装起来门槛不高，两条路。想快速上手，pip 装个 SDK 配一下就行：

```bash
pip install opik
opik configure
```

然后给函数加个 `@track` 装饰器，之后的调用就会自动记进 Opik。想本地自托管整个平台，克隆仓库跑一下脚本：

```bash
git clone https://github.com/comet-ml/opik.git
cd opik
./opik.sh
```

Opik 是 Apache-2.0 协议，完整平台（含后端、Web、评测、Prompt 管理）都能免费自托管，数据不用出你自己的环境。从发布到现在已经攒了 2.2 万+ Star，今天一天涨了 766，势头不弱。它最适合正在把 LLM 应用或 Agent 从原型推向生产、又不想把可观测性交给闭源 SaaS 的团队；如果只是偶尔调调 API，那这套东西对个人来说会有点重。
