AI 编程助手越来越强，但一个毛病始终没改掉：太爱读文件。接到任务，先 grep 一遍，再 cat 一个文件、又一个文件，把整个代码库往上下文窗口里塞。WordPress 核心的 PHP 代码大约 520 万 token，相当于 26 个满格的上下文窗口，一个 Agent 根本读不完，却还是要硬读。

![XERJ 演示：启动、批量导入、检索、向量检索、实时看板](https://raw.githubusercontent.com/xerj-org/xerj/HEAD/docs/media/demo-poster.png)

XERJ 换了一种思路：与其让 Agent 一个个文件读进来，不如先把整个目录做成一个可查询的索引，Agent 用「查询」代替「阅读」，只拿它真正需要的那几段。这个 Rust 写的单文件二进制，最近在 GitHub 上蹿得很快，已经攒了 7000 多 Star，光今天就涨了 1600 多。

**项目地址：**https://github.com/xerj-org/xerj

**核心就一条命令**

`xerj autoindex <文件夹>`——把命令指向任何目录，它会自动识别每个文件是什么。代码走 tree-sitter 解析，符号和行号都保留，不是拍平成纯文本；CSV、JSON、SQLite、PDF、DOCX、Excel、EPUB、Jupyter notebook、日志、邮件（含 Google Takeout 导出）各归各的索引。整个过程没有 schema 要写，没有 pipeline 要配。它对外讲 Elasticsearch 的 API，一致性测试 1366/1369 通过，所以 Kibana、现成的客户端、已有的工具链都能直接接上，不用改。

![XERJ 看板：AI 概览](https://raw.githubusercontent.com/xerj-org/xerj/HEAD/docs/media/dashboard-ai-overview.png)

**实测省了多少 token**

最让人信服的是它自己公布的一份对照实验：8 个任务、4 种语言、每组 16 次运行，用真实的 `claude -p` token 计数。结果是这样的——

| 方案 | 输出 token | 花费 | 解决率 |
|---|---:|---:|---:|
| 纯靠模型记忆 | 260,916 | $11.18 | 11/16 |
| grep 驱动 | 26,477 | $3.27 | 16/16 |
| XERJ 索引 | 9,982 | $1.58 | 16/16 |

同样是 16/16 全解决，XERJ 的输出 token 只有 grep 方案的约三分之一（2.7 倍差距），比纯靠记忆少了 26 倍，花费也从 11 美元降到 1.58 美元。项目方也承认这套方案的边界：在模型已经背熟的流行公共库上，它是中性甚至有害的；真正的价值在私有、内部、小众或训练截止日期之后的代码上。日常开发里，用户反馈大概能省 5 倍 token。

![XERJ 看板：向量索引](https://raw.githubusercontent.com/xerj-org/xerj/HEAD/docs/media/dashboard-vector-index.png)

**装起来只要一条命令**

```bash
curl -fsSL https://xerj.org/get | sh
xerj --insecure --data-dir ./data &
xerj autoindex ~/my-project
```

一条命令装好，后台起服务，再指向你的项目目录就行。要接 Claude Code 或 Cursor，还有 `xerj init` 一键把 MCP 和 skill 接进去；Windows 上用 `irm https://xerj.org/get.ps1 | iex`。除了「reference coding」（把相近的开源项目克隆下来、先索引、写代码前先检索别人怎么解决的），它也能当本地 RAG、代码安全审计、日志分析、Agent 长期记忆（`/_memory` 命名空间）用。

客观地说，它现在还是 1.0 之前的 RC 阶段，`--insecure` 这个默认开发模式关掉了 TLS 和鉴权，只适合单机本地用；集群能力和日志检索精度也还在打磨。但对每天跟 AI 编程助手打交道、又心疼 token 的人来说，这个「先索引、再查询」的思路，方向是对的，也值得装上试一把。
