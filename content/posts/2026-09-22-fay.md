数字人这两年很热闹：虚拟主播、虚拟教师、智能客服，各路厂商都在往这个方向扎。但真正做过落地的人都知道，最难的从来不是那张「脸」——UE5 捏个角色、Wav2Lip 对口型，都有现成方案。难的是让数字人真正「活」起来：听懂用户说什么、接上大模型思考、再把结果说出去、顺手调一下业务系统。这一步，大多数团队还在手写胶水代码，把 ASR、LLM、TTS、业务接口一个个硬拼起来。

Fay 就是冲这个来的。它是一个开源的数字人 Agent 框架，核心就干一件事：把数字人和大模型、业务系统之间的那层对接标准化。向上，它适配各种数字人形态——2.5D、3D、移动端、PC、网页都能接；向下，它接入各式大语言模型，OpenAI 兼容接口和 DeepSeek 都能自由切换，换模型不用改架构。中间还留了 ASR、TTS 的插槽，识别和发声模块想换就换。

**项目地址：** https://github.com/xszyou/Fay

![Fay 数字人对话界面](https://raw.githubusercontent.com/xszyou/Fay/HEAD/readme/chat.png)

两个点值得一提。一是它把「能干活」这件事做扎实了：支持 Agent 自主决策工具调用，数字人不再只是照着脚本念稿，而是可以自己判断该调哪个工具；还支持 MCP 工具管理（SSE、Studio 两种模式），把外部工具接入做成了一套标准流程。再叠加仿生记忆、唤醒打断、多路并发这些能力，它给的是一个能放进生产环境的骨架，而不是演示 demo。

二是它的开放程度。项目 GPL-3.0 协议，README 里明明白白写着「完全开源，商用免责」，而且支持全离线使用，数字人模型、大模型、ASR、TTS 都可以换成自己的一套，数据不出内网。这在数字人方案普遍云化、按次收费的现状下，算是一股清流。从热度看，项目已经攒了 1.35 万 Star，光今天就涨了 344 个。

![Fay 控制管理中心](https://raw.githubusercontent.com/xszyou/Fay/HEAD/readme/controller.png)

装起来不难，就几步。环境要 Python 3.12，Windows、macOS、Ubuntu 都能跑（Ubuntu 先补 gcc 和 portaudio）。装依赖、启动：

```
pip install -r requirements.txt
python main.py start -config_center d19f7b0a-2b8a-4503-8c0d-1a587b90eb69
```

启动后浏览器打开 http://127.0.0.1:5000 就是管理页面。README 里那句配置参数用的是公共资源，速度慢，正式用建议换成自己的 Key。

![Fay MCP 工具管理](https://raw.githubusercontent.com/xszyou/Fay/HEAD/readme/mcp.png)

客观说一句：它给的是骨架，不是开箱即用的成品。适合已经在做数字人项目、又不想自己维护一套对接层的团队，也适合想给大模型接上业务后台的开发者；如果只是想要一个现成的虚拟形象聊天，那它的上手成本可能比预期高一点。
