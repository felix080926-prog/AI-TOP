大模型本地部署的痛点，说来说去就那么几个：显存不够、速度太慢、配置太复杂。云端 API 倒是省事，可每发一条消息，prompt 和回复都得绕一圈别人的服务器。

WebLLM 走的是第三条路——把大模型推理整个搬进浏览器。这是一个由 MLC AI 社区维护的高性能浏览器内推理引擎，底层用 WebGPU 做硬件加速，模型权重下载到本地缓存后，所有推理都在本机完成，不需要后端服务器，也不产生任何 API 费用。

**项目地址：**https://github.com/mlc-ai/web-llm

![WebLLM 架构与浏览器内对话示意](https://blog.mlc.ai/img/webllm-engine/arch-and-chat.gif)

从 2023 年发布到现在，这个仓库已经攒了 1.9 万多 Star，光最近一天就涨了 600 多。npm 上 `@mlc-ai/web-llm` 的周下载量也有七万多，说明它不是 demo，而是真有人拿它做产品。

## 对前端最友好的一点：接口跟 OpenAI 一模一样

WebLLM 最聪明的地方，是直接对齐了 OpenAI 的 chat completions API。前端开发者不用学一套新东西——流式输出、JSON 模式、seed 复现、function calling，字段跟调云端接口完全一致，只是把请求目标从 `api.openai.com` 换成了一个跑在浏览器里的引擎实例。它甚至还支持结构化 JSON 生成，用 XGrammar 在 WebAssembly 里做约束解码，让模型稳定吐出符合 schema 的 JSON。

![WebLLM 的 OpenAI API 兼容调用示例](https://blog.mlc.ai/img/webllm-engine/api.png)

模型支持上也不含糊：Llama 3、Phi 3、Gemma、Mistral、Qwen（通义千问）这些主流开源模型都能直接加载，还能编译自己的 MLC 格式定制模型。配合 Web Worker 和 Service Worker，推理跑在独立线程里，页面该流畅还是流畅。

## 真正打动人的，是"数据不出浏览器"

比起性能，WebLLM 更大的价值在隐私。模型缓存到本地后，之后的每一次对话都在浏览器内完成，prompt 和回复不经过任何第三方服务器。这对医疗、金融这类数据敏感的场景，意义比省那点 API 费用大得多。

![WebLLM 性能基准](https://blog.mlc.ai/img/webllm-engine/perf.png)

当然它也不是万能药。首次加载要下载模型权重，体积不小；推理速度受浏览器 WebGPU 能力限制，跟高端 GPU 没法比。所以它更适合边缘推理、离线产品、隐私优先的前端应用，而不是替代服务端的重推理。

对想在网页里塞个不依赖云端的 AI 能力、又不想重新学一套接口的团队来说，WebLLM 是个值得放进工具箱的选项。

项目地址：https://github.com/mlc-ai/web-llm
