大模型本地部署的痛点，说来说去就那么几个：显存不够、速度太慢、配置太复杂。放到手机这类端侧设备上，问题更尖锐——内存预算只有几百兆、算力是桌面端的零头，还要顾虑发热和功耗。于是不少团队干脆放弃端侧，把所有请求都往云端推。

但端侧推理这件事，阿里巴巴已经默默做了很多年，而且跑得比大多数人想象的要顺。这家公司把一套推理引擎塞进了淘宝、天猫、优酷、钉钉、闲鱼等 30 多个 App，覆盖直播、短视频、搜图、风控等 70 多个场景——它就是 MNN，一个主打「快、小、轻」的端侧深度学习推理引擎。这套东西从 2019 年开源至今，已经攒了 1.6 万 Star，最近还在涨。

**项目地址：**https://github.com/alibaba/MNN

![MNN 官方 banner](https://raw.githubusercontent.com/alibaba/MNN/master/doc/banner.png)

MNN 眼下最值得说的是它对端侧大模型的投入。围绕引擎，阿里做了一整套 MNN-LLM 运行时，专门解决「把大模型部署到手机、PC、IoT 设备上」这件事。通义千问、百川、智谱、LLaMA 等主流开源模型都能转成 MNN 格式在本地跑，支持 FP16 和 Int8 量化，模型体积能压掉 50% 到 70%。今年 7 月底发布的 3.6.1 版本又加了高通 Hexagon DSP 后端，在骁龙 8 Elite 上跑 Qwen3-0.6B 的 W4 量化模型，prefill 速度冲到每秒 2667 token，差不多是纯 CPU 路径的 8 倍——这个数字基本意味着手机上的本地大模型从「能用」跨到了「好用」。

另一个特点是轻。Android 端核心 so 只有 800KB 左右，iOS 静态库全量约 12MB，用 MNN_BUILD_MINI 还能再砍掉约 25%。后端覆盖也很全：ARM/x86 CPU、OpenCL、Vulkan、Metal、CUDA，外加 CoreML、华为 HiAI、高通 QNN 这些 NPU 通路。同一份模型，基本不用改代码就能在手机、电脑、嵌入式设备上跑，省掉了反复做模型转换和适配的破事。

![MNN 架构图](https://raw.githubusercontent.com/alibaba/MNN/master/doc/architecture.png)

装起来也不麻烦。想用 Python 快速试一把，直接装官方包就行：

```bash
pip install -U MNN
```

要做端侧大模型，就按 README 里的 llmexport 流程，先把模型导成 ONNX、再转成 MNN 格式并做 4bit/8bit 量化；不想折腾的话，直接装官方 MNN Chat App，就能在安卓手机上离线跑多模态对话（文生文、图生文、语音、文生图都支持）。

![MNN Chat 多模态对话界面](https://raw.githubusercontent.com/alibaba/MNN/master/apps/Android/MnnLlmChat/assets/image_home_new.jpg)

MNN 不是那种每周上新热榜的玩具，它是被阿里线上业务常年压测过的生产级引擎——相关设计还写进了 OSDI'22 和 MLSys 2020 的论文，Apache 2.0 协议。它适合谁用？做端侧或边缘 AI 的团队，尤其是要在手机、IoT 设备上跑大模型、又不想被推理框架的体积和性能拖后腿的人。对个人开发者来说，想低成本体验本地大模型，拿它跑个 Qwen 小模型也是条靠谱的路。
